# REVIEW.md

Defects found in the starter `app/main.py` (line numbers refer to the starter file).

| # | Where (function / line) | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `MongoClient(...)` (l.22), `datetime.now()` (l.82, 102), `fromtimestamp` (l.102) | Datetimes are naive and use the server's local clock, so results depend on the machine's time zone. PyMongo also returns naive datetimes, so they can't be safely compared with IST values. | Run the app on a server with a non-UTC time zone: stored times and dates shift. Subtracting naive and aware datetimes raises `TypeError`. | `tz_aware=True` on the client; every instant is an aware UTC datetime; epoch-ms conversion in `to_ms`/`from_ms`; dates computed explicitly in IST. |
| 2 | `compute_late_minutes` (l.33-37) | Builds shift start from the punch-in's own (UTC/naive) date and clock, not IST, and ignores overnight shifts. `int(seconds/60)` floors before comparing, so 10 min 30 s becomes `10` and is treated as not late (rule says strictly more than 10:00). Seconds are not truncated. | Shift 09:30, punch-in 09:40:30 returns 0 instead of 10; an overnight shift punching in at 01:00 gets a nonsense value. | `shift_bounds()` builds the shift start in IST for the attendance date (also for overnight shifts); compare in whole seconds: late only if `> 600 s`, then `floor(seconds/60)`. |
| 3 | `compute_work_hours` (l.40-41) | `round()` on a float is not half-up (banker's rounding plus binary float error); seconds not truncated. | 18 s of work (0.005 h) or a value like 2.675 rounds the wrong way. | Integer maths: `(secs*200 + 3600) // 7200 / 100` gives exact half-up to 2 decimals. |
| 4 | `compute_overtime` (l.44-47) | No 30-minute minimum (`max(0, ...)` returns any minutes after shift end); an overnight shift end is not moved to the next day; `end` is aware but `punch_out` from the DB is naive, so subtraction raises `TypeError`. | Punch-out 5 minutes after shift end returns 5 (should be 0); overnight shift punch-out at 06:40 gives a huge negative / 0. | Overtime counted only when whole minutes >= 30; shift end built by `shift_bounds()` (next day for overnight); both sides aware. |
| 5 | `EmployeeIn` (l.53-60) | No validation: bad `emp_code`, bad e-mail, malformed shift times, impossible dates (`2026-02-30`), `shift_start == shift_end`, over-long strings are all accepted. | POST `emp_code: "abc"` returns 201. | Field patterns/length limits, a `joined_on` date validator, and a model validator for equal shift times (all give 422). |
| 6 | `PunchInIn` (l.63-66) | `punched_at` accepts any int (seconds, negatives); `status` accepts any string, including `ABSENT`, `LEAVE` or junk. | POST `{"status":"ABSENT"}` is stored; `punched_at` in seconds gives a 1970 date. | Strict int range for epoch ms (rejects seconds/floats/strings) and `Literal["PRESENT","WFH","ON_DUTY"]`. |
| 7 | `health` (l.72-74) | Always returns ok, even when MongoDB is down. | Stop MongoDB; `/health` still says ok. | Pings MongoDB, 503 on failure. |
| 8 | `create_employee` (l.77-85) | Check-then-insert race and no unique index: two simultaneous requests can both pass the check and create duplicates. `created_at` is naive local time and returned as a datetime, not epoch ms. | Fire 20 identical POSTs in parallel and count the 201s. | Unique index on `emp_code` created at startup; `insert_one` and catch `DuplicateKeyError` -> 409; `created_at` returned as epoch ms. |
| 9 | `list_employees` (l.88-96) | `skip = page*page_size` skips the first page (should be `(page-1)*page_size`); `total` counts all employees, ignoring the department filter; no sort, so the order is not deterministic; `page`/`page_size` unvalidated (`page=0` gives a negative skip). | `GET /employees?department=Sales` shows `total` for the whole company; page 1 starts with the 21st employee. | Correct skip, `count_documents(q)` on the same filter, `sort emp_code asc`, `Query(ge=1, le=100)` validation. |
| 10 | `punch_in` (l.99-121) | Unknown employee -> `emp` is `None` -> `TypeError` -> 500 instead of 404. Date taken from the server's local clock instead of IST and with no overnight rule (R1). Milliseconds not truncated. `if body.punched_at` treats a falsy value as missing. Check-then-insert race (two requests can both succeed). Response has an `id` (the Mongo `_id`, which must never be exposed), and `punch_in` as a datetime instead of epoch ms. | POST with an unknown `emp_code`; parallel punch-ins; punch-in at 00:30 IST. | 404 check; `attendance_date()` in IST with the overnight rule; `from_ms` truncates to seconds; unique index (`emp_code`,`date`) plus `DuplicateKeyError` -> 409; `record_out()` returns epoch ms and no `_id`. |
| 11 | `list_attendance` (l.124-150) | Loads the entire collection into memory and sorts/paginates in Python (breaks at ~100k records); sorts by date only (no `emp_code` tie-break); no index; returns `id` and raw datetimes; `date_from > date_to` and invalid dates are not rejected; `page`/`page_size`/`status` unvalidated (`page=0` slices from the end); documents with missing/`null` fields are returned as-is. | Time it with 100k documents; `?page=0`; `?date_from=2026-08-01&date_to=2026-07-01`. | Query, sort, skip and limit done in MongoDB with a `(date desc, emp_code asc)` index; `count_documents` for the total; validation (422); `record_out()` applies defaults for missing/null fields. |
| 12 | Whole file | No indexes are created, and `punch-out`, `PATCH`, analytics and explain are missing. | `explain` shows `COLLSCAN`. | Indexes created idempotently at startup; missing endpoints implemented. |

## Looked at, decided NOT a defect

- `load_dotenv()` does not override variables that are already set, so real environment variables win, as the spec asks.
- `IST = timezone(timedelta(hours=5, minutes=30))` is correct (India has no daylight saving time), so I kept it.
- Comparing `date` strings with `$gte`/`$lte` is correct, because ISO `YYYY-MM-DD` strings sort the same as the dates they represent.
- `doc.pop("_id", None)` after `insert_one` is fine for hiding the `_id` (the real problem there was only the `created_at` format).
